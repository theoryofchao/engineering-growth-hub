# ADR 0049: Four new module 70 sessions for Anthropic's Claude Code curriculum levels, after an explicit overlap audit

## Status

Accepted

## Context

The user pasted a 6-item list from what's apparently Anthropic's own official Claude Code learning curriculum (persistent project instructions via CLAUDE.md; Level 4 Workflows; Level 5 Customization; Level 6 Tools & MCP; Level 7 Subagents; Level 8 Agent SDK) and asked for it to be meaningfully incorporated into module 70 (AI-Assisted Software Development, already 8 sessions deep), with the explicit instruction to ensure nothing is repeated. Module 70 already covers a large amount of Claude Code material from a *practitioner-habits* angle (sessions 1, 3: repo context files/CLAUDE.md as onboarding; session 6: memory/settings precedence; session 7: Skills, Hooks, MCP's cost tradeoff, LSP; session 8: Trinity/delegation/worktrees, sandbox defaults, CI/CD). Before writing anything, each of the 6 items was checked against this existing coverage, heading by heading, to find what's genuinely missing versus what would just restate existing content under a new title.

## Decisions

1. **Two of the six items were found to be already thoroughly covered and got no new session**, reported to the user rather than silently duplicated:
   - CLAUDE.md / persistent project instructions -- sessions 1 ("Repository Context Files Do the Onboarding"), 3 ("CLAUDE.md Is an Onboarding Doc, Not a Wishlist"), and 6 (memory/settings precedence hierarchy).
   - Customization (skills, hooks, permission configuration) -- session 7 (Skills, Hooks directly) and sessions 6/8 (permission modes, sandbox defaults).
2. **Four new sessions were added for the four genuinely uncovered angles**, each one deliberately scoped to the specific slice existing sessions *don't* already cover, not a broader retelling of the same topic:
   - **Session 9 (subtopic 70.13), "Staging a Feature as a Workflow, Not One Giant Request"** (Level 4). Existing session 1 covers *why* to separate planning from implementation as a habit; this session covers the mechanical stage structure instead -- Plan Mode's tool-enforced approval gate, decomposing a plan into independently verifiable increments, per-increment verification gates, and the commit/PR as the natural reviewable/revertible unit.
   - **Session 10 (subtopic 70.14), "MCP in Practice: Local Servers, Remote Servers, and the Trust Each One Requires"** (Level 6). Existing session 7 covers *whether* to add an MCP server (token-cost tradeoff); this session covers the mechanics of actually connecting one -- local stdio vs. remote HTTP/OAuth transports, `claude mcp add` syntax, scopes (local/user/project, including the shared, committed `.mcp.json` case), and the security-trust framing of a new server as new code with real access.
   - **Session 11 (subtopic 70.15), "Custom Subagents: Configuration, Isolation, and Why a Summary Isn't Proof"** (Level 7). Existing sessions 1/4/8 cover *when/why* to delegate (parallelizable work, Trinity escalation, worktrees); this session covers the configuration layer instead -- a subagent definition's tool-list as an actual capability restriction (not a prompt), context isolation (a subagent starts cold, nothing from the parent conversation carries over automatically), and the structural reason a subagent's returned summary is a claim to verify rather than a transcript to trust -- drawing directly on this session's own operating environment's documented behavior.
   - **Session 12 (subtopic 70.16), "Building on the Agent SDK: From Interactive Tool to Custom Application"** (Level 8). Zero prior coverage -- the entire module assumed an interactive terminal session; this session covers the SDK as the same underlying engine embedded in a custom, unattended application: `query()` vs. `ClaudeSDKClient`, in-process custom tools (`@tool` + `create_sdk_mcp_server`) versus the external MCP servers from session 10, and `can_use_tool` as code-defined permission logic replacing the human-in-the-terminal approval step.
3. **Every technical claim about the Agent SDK and MCP mechanics was verified against official sources before writing**, not drawn from general impression: `code.claude.com/docs/en/agent-sdk/overview`, `.../python`, and `code.claude.com/docs/en/mcp`, plus GitHub's own official MCP server (`github/github-mcp-server`) as the session 10 worked example -- all confirmed live via `curl` both during drafting and again before shipping.
4. **`CURRICULUM.md`'s module 70 subtopic list was extended (70.13-70.16)** to name all four new areas, following the exact precedent of how 70.9-70.12 were added when sessions 5-8 were authored (ADR 0011/0015).
5. **Two existing backend tests hardcoded module 70's session count (8) and needed bumping to 12** -- `test_seed.py::test_seed_all_imports_full_curriculum_map` and `test_learning_sessions.py::test_section_sessions_lists_every_lesson_in_the_section_for_navigation` -- exactly the known, documented pattern from `content/curriculum/README.md` ("both hardcode a session count... that a new session will need bumping").
6. **First-draft bias audits were heavier than average across all four sessions** (1-2 flagged per session, one session needing two rebalancing passes) -- consistent with the now-established expectation that this is normal, not a sign of a drafting mistake.

## Consequences

- `pytest` 139 passed after bumping the two session-count assertions (137 initially failed on 2, both expected and explained above, not a real regression).
- Verified against the live dev stack: all 4 new sessions render on the section page and individually, all 4 reference links (GitHub's MCP server, Claude Code's MCP docs, Agent SDK overview, Agent SDK Python reference) render with correct hrefs and resolve live, and one quiz per session was answered correctly through the real UI with zero console/page errors. All test-generated submission/review-state/progress rows were deleted afterward.
- Mid-verification, the entire `docker compose` dev stack (api/db/web) was found to have exited on its own (not from any command run in this session) -- restarted cleanly with `docker compose up -d` and reverified once healthy; flagged here as an external interruption, not a content or code issue.
- Module 70 is now 12 sessions, covering both the practitioner-habits material it already had and the four specific mechanical/configuration layers (staged workflows, MCP transport/trust mechanics, subagent configuration/isolation, and the Agent SDK) that the user's pasted curriculum list named and that weren't previously covered.

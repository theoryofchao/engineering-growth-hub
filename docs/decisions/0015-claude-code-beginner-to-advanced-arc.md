# ADR 0015: Claude Code beginner-to-advanced arc (fundamentals + advanced orchestration sessions)

## Status
Accepted

## Context
User request: consume the content of `github.com/FlorianBruniaux/claude-code-ultimate-guide` and incorporate it meaningfully, so the module's Claude Code coverage spans beginner through advanced rather than jumping straight to the feature-deep-dive session ADR 0012 added.

Investigation before writing content:
- The repo ships `llms-full.txt` (condensed overview + cheatsheet + FAQ, ~1,000 lines) specifically for AI consumption, plus a ~26,700-line `guide/ultimate-guide.md` with the full prose. Read the condensed file in full, then fetched the specific sections of the full guide that weren't in the condensed version but were directly relevant (the Trinity pattern, §9.1-9.2's composition patterns) rather than attempting to ingest all 26,700 lines.
- The source guide is unusually version- and date-specific (exact CLI flags, keyboard shortcuts, per-model pricing, dated "verified as of" claims). Treated this the way session 2 already treats productivity-claim sources: extracted durable concepts (the Master Loop mental model, memory precedence, permission-mode spectrum, Trinity, sandbox defaults) rather than transcribing command tables or pricing that will be stale within weeks — consistent with this module's existing position that lesson content teaches judgment, not command memorization.
- Existing sessions 1-5 (general agentic-workflow habits) and the session added in ADR 0012 (Claude Code's native toolkit — MCP/Skills/Hooks/LSP) already assumed a working familiarity with the tool. Nothing in the module covered the tool's actual execution model, memory/settings precedence, or permission spectrum — genuine beginner-level gaps, not duplicates of existing content. Nothing covered composing primitives for the hardest problems (Trinity, multi-agent delegation) or hardening a setup for CI/production — genuine advanced-level gaps.
- Found the DB already held real data against this topic's sessions: 4 `exercise_submissions` and 5 `study_sessions` (the user's own usage while building/testing the app). Renumbering an existing session's `sequence` risks the seed loader's upsert-by-sequence mechanism silently reattaching that historical data to unrelated content, since it updates rows in place rather than tracking stable identity across a resequence. Presented this tradeoff to the user directly rather than picking a side silently (append-only, preserving the data exactly, vs. clear-and-renumber, for a clean reading order) — they chose to clear.

## Decisions
1. **Added two new learning sessions**, bracketing the existing ADR 0012 session:
   - Sequence 6, `06-claude-code-fundamentals.json`, "Claude Code Fundamentals: Installation, the Mental Model, and Memory" (beginner) — the Master Loop (single loop, small general toolset, "less scaffolding, more model"), context/compaction, the project-vs-personal memory and settings precedence, the permission-mode spectrum plus Plan Mode as a structural (not just habitual) guarantee, and the WHAT/WHERE/HOW/VERIFY request pattern tied back to session 1's "give the agent a check it can run."
   - Sequence 8, `08-advanced-orchestration-and-production-hardening.json`, "Advanced Claude Code: Orchestration, the Trinity, and Production Hardening" (advanced) — the Trinity pattern (Plan Mode → deep reasoning → structured step-by-step reasoning, reserved for genuinely hard problems), composition patterns (parallel multi-agent delegation, tied back to session 4's "would two humans need to coordinate" independence test; iterative critique), the sandbox's two layers and its actually-permissive-by-default read policy (extends session 7's Hooks-based `.env` protection with the sharper point that the sandbox itself isn't a credentials guarantee), headless/CI mode, and a paused-then-resumed vendor billing announcement as a concrete case of this module's "verify current state, don't trust an old announcement" theme from session 2.
   - Sequence 7 is the session ADR 0012 added, resequenced from 6 to 7 and renamed from `06-native-toolkit-mcp-skills-hooks-lsp.json` to `07-native-toolkit-mcp-skills-hooks-lsp.json` (content unchanged except one intro sentence acknowledging the new preceding fundamentals session). This gives a clean 6→7→8 beginner→intermediate→advanced reading order matching the topic's nav, which lists sessions by `sequence`.
2. **Cleared historical data for this topic before reseeding**, per the user's explicit choice: deleted (in FK order) `exercise_submissions`, `exercises`, `notes`, `content_blocks`, `study_sessions`, then `learning_sessions` for `70-ai-assisted-software-development`, leaving the `topic`/`module`/`domain` rows untouched. This avoided the alternative risk of the sequence-6 resequencing silently reattaching the 4 old submissions / 5 old study sessions to unrelated new content.
3. **Added subtopics `70.11` and `70.12`** to `CURRICULUM.md`, additive per the file's ID-stability rule, matching the new fundamentals and advanced-orchestration sessions respectively.
4. **Sized and audited both new sessions against the established rule** (content/curriculum/README.md, ADR 0013): both landed within the 900-1800 char / 6-7 block target after two rounds of padding undersized blocks, and the answer-length-bias audit (ADR 0009) required several rounds of rebalancing — one exercise in particular (contrasting a concrete, well-formed request against vague ones) has a correct answer that's inherently more specific text, which naturally runs longer; fixed by padding the vague distractors with filler qualifiers rather than stripping the concrete example down to where it lost its teaching point.

## Consequences
- `pytest`: 29 tests pass. Updated the same two hardcoded session-count assertions as ADR 0011/0012: `test_seed.py`'s `len(ai_topic.learning_sessions) == 6` → `8`, `test_learning_sessions.py`'s `len(body["topic_sessions"]) == 6` → `8`.
- Verified against the live stack: reseeded from a clean slate for this topic and confirmed via direct SQL that all 8 sessions landed with the expected block/exercise counts (7/6/6/6/6/7/7/6 blocks, 6/5/7/7/4/5/6/4 exercises for sequences 1-8), and via the live API that `topic_sessions` now lists the beginner session before the toolkit and advanced sessions, matching the intended reading order.
- The 4 `exercise_submissions` and 5 `study_sessions` that existed against this topic before this change are gone — confirmed with the user first, and confirmed they were the user's own test/dev activity rather than data to preserve.
- Deliberately did not transcribe the source guide's cheatsheet (exact slash commands, keyboard shortcuts, per-model pricing) into lesson content — that material is real but volatile, and this course has consistently treated volatile/unverified specifics as something to flag or omit rather than teach as fact (see session 2's whole thesis, and the LSP-speedup caveat already in session 7).

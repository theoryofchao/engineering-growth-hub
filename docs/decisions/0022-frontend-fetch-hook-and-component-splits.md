# ADR 0022: Shared fetch hook, and splitting two oversized components

## Status
Accepted

## Context
Continuing the architecture sweep: the audit found 5 of 9 non-trivial components (`health-status.tsx`, `dashboard-summary.tsx`, `topic-list.tsx`, `topic-overview.tsx`, `lesson-content.tsx`) independently reimplementing the identical fetch+`AbortController`+loading/error/success lifecycle verbatim. A closer look (this session) found `pomodoro-timer.tsx`'s mount-fetch has the same shape but its mutations (`start`/`sendAction`) never used `AbortController` at all, and `exercise-quiz.tsx` is a one-shot POST with no mount fetch — neither is a clean fit for a shared *fetch-on-mount* hook. Separately, `content-blocks.tsx` (305 lines) and `pomodoro-timer.tsx` (300 lines) each mix multiple unrelated concerns.

## Decisions
1. **New `useFetch<T>(path: string | null)` hook** (`src/hooks/use-fetch.ts`): the `loading`/`error`/`not-found`/`success` fetch-on-mount lifecycle, parameterized by path (prepends `API_BASE_URL` internally) with `path: null` to skip fetching. Adopted by exactly the 5 components confirmed to duplicate this verbatim. **Deliberately not adopted** by `pomodoro-timer.tsx` or `exercise-quiz.tsx` — retrofitting the timer's richer state machine onto a generic hook carries real regression risk for a live study-timer widget for low payoff (its fetch logic isn't duplicated elsewhere), and `exercise-quiz.tsx` has no mount-fetch lifecycle to unify in the first place. Noted here as a scoped-out decision, not an oversight.
2. **`content-blocks.tsx` split**: extracted `useNoteDraft<B extends {id, note}>(blocks, setBlocks)` (`src/hooks/use-note-draft.ts`) — owns which block's notes are open, the unsaved draft, save/delete persistence (PUT/DELETE `/content-blocks/:id/note`), and the dirty-check confirm/alert flow. `content-blocks.tsx` keeps page/slide navigation and rendering, calling the hook's `switchTo`/`save`/`remove` instead of its own `switchActiveBlock`/`handleSave`/`handleDelete`. Pure code movement — the hook is generic over any block shape with `id`/`note`, so it type-checks against `content-blocks.tsx`'s existing `Block` type with no changes to that type.
3. **`pomodoro-timer.tsx` split**: extracted `useElapsedDisplay(isRunning)` (`src/hooks/use-elapsed-display.ts`) — the pure "ticking clock" math (recomputing `baseline + time since last server snapshot` once a second), exposing `{ displaySeconds, setBaseline }`. The component calls `setBaseline(session.elapsed_seconds)` at exactly the point the original code set `fetchedAtRef.current = Date.now()` (inside `applySession`, run after every create/restore/pause/resume/complete), preserving the original reset timing exactly rather than inferring it from a value-change comparison (which could miss a reset if `elapsed_seconds` happened to repeat across two consecutive snapshots). Session-lifecycle fetch calls (`start`/`sendAction`/localStorage) stay in the component per decision 1.
4. **Found and fixed a real lint violation while extracting**: `useElapsedDisplay`'s initial `useRef` value originally called `Date.now()` directly during render, which `react-hooks/purity` correctly flags (impure call in render). Fixed by initializing `fetchedAt: 0` — safe because ticking only starts once `isRunning` is true, which only happens after `setBaseline` has already run at least once.

## Consequences
- `npx vitest run`: 89 tests pass (71 before this slice + new tests for `useFetch` (7), `useElapsedDisplay` (5), `useNoteDraft` (6)); every existing component test for the 7 touched components passed unchanged, confirming behavior-preserving extraction.
- `npx eslint .`, `npx prettier --check .`, `npx tsc --noEmit` all clean.
- Verified against the live dev stack with a real browser (Playwright): started a Pomodoro session on `/learning/3` and confirmed the displayed clock advanced from `0:00` to `0:02` over ~2 real seconds (the ticking math still works after the split); opened a content block's notes, saved a note, reloaded the page, and confirmed the note persisted (the note-draft extraction still works); cleaned up the test note and verified its removal via SQL afterward.
- No API, schema, or route changes — frontend-only, and no response-shape changes for any of the five hook-adopting components.

# ADR 0026: Worked examples as a collapsed accordion on content blocks

## Status
Accepted

## Context
User feedback: slides should teach concepts in prose but also show concrete examples, collapsed by default so a long code/config sample doesn't push past the slide's body (the sizing rule in `content/curriculum/README.md` caps a block at ~900-1800 characters). The immediate trigger case: the "Repository Context Files Do the Onboarding" slide (`content/curriculum/ai-assisted-software-development/01-coding-agent-habits.json`, session 1, block 3) previously inlined one short CLAUDE.md snippet as a fenced code block inside `body` — which the frontend renders as plain prose (`whitespace-pre-wrap`, no Markdown parsing), so the backticks and fence markers showed up literally instead of as code. The user also asked for a second, fuller real-world-shaped CLAUDE.md example on that same slide.

## Decisions
1. **New `examples` field on `ContentBlock`**, not a Markdown renderer for `body`. A list of `{label, content}` objects, stored as JSON (`db.Column(db.JSON, nullable=False, default=list)`), added via migration `2e5647ba1806`. Rendering examples as distinct, labeled, monospace blocks is a better fit than trying to make freeform prose support embedded code — it also means a block's prose and its worked example(s) can be edited/reordered independently in the source JSON.
2. **Native `<details>`/`<summary>` per example**, not a stateful accordion component — same pattern already used by `ContentWidthContainer` and `tier-legend.tsx` (ADR 0025). No open/close state to own, keyboard/accessibility behavior comes for free, and it matches the file's existing conventions instead of introducing shadcn/ui or Radix (neither is actually installed in `apps/web` despite being named in `docs/ARCHITECTURE.md`'s aspirational stack).
3. **New `ExampleAccordion` component** (`apps/web/src/components/example-accordion.tsx`), rendered in both page view and slide view of `ContentBlocks`, directly under the block's body and above its exercises. Renders nothing when `examples` is empty, so existing blocks with no examples are unaffected.
4. **`examples` is optional on the frontend type** (`examples?: ContentExample[]`), defaulting to `[]` at the render site, rather than updating every existing test fixture across `content-blocks.test.tsx` / `lesson-content.test.tsx` to add an empty array — those fixtures predate this field and aren't otherwise part of this change.
5. **Content change scoped to the one requested slide.** The slide's `body` was edited to drop the inlined minimal example and add a sentence pointing at "the two examples below"; `examples` now holds that original minimal snippet plus a new, fuller CLAUDE.md (onboarding doc, repo layout, commands, coding standards, architectural boundaries, AI-agent-behavior section) modeled on this project's own CLAUDE.md shape but describing a similarly-structured hypothetical project. Body length after the edit is 1013 characters, still within the session's sizing rule. No other session's content was touched.

## Consequences
- Backend: `apps/api/tests/test_seed.py` (`test_seed_all_imports_block_examples`) and `apps/api/tests/test_learning_sessions.py` updated/added. `pytest`: 73 passed. `ruff check` / `mypy`: clean.
- Frontend: `apps/web/src/components/example-accordion.test.tsx` added; `content-blocks.tsx` and `lesson-content.tsx` updated to pass `examples` through. `vitest run`: 110 passed. `tsc --noEmit` and `eslint`: clean.
- Verified against the live dev stack with a real browser (Playwright): the "Repository Context Files" slide shows an "Examples" section with both entries collapsed by default in both page and slide view; expanding each renders the labeled summary and a monospace `<pre>` block, confirmed for both the short snippet and the ~6,000-character fuller example (including its ASCII repo-tree block, which stays legible in `<pre>`).
- `examples` is additive and backward compatible — every pre-existing content block seeds with `examples: []` and renders unchanged.
- Not done: no Markdown rendering was added to `body` itself, so a future author who puts a fenced code block directly in prose text will hit the same literal-backticks issue this ADR fixed for this one slide. Moving an inline example into `examples` is the documented way around that for now; a general Markdown renderer for `body` is a separate decision.

# ADR 0001: Milestone 0 scaffold decisions

## Status
Accepted

## Context
`docs/ROADMAP.md` Milestone 0 calls for a monorepo with Next.js/TypeScript and Flask/Python, Postgres via Docker Compose, a health endpoint, a frontend page consuming it, README instructions, `.env.example`, and basic automated tests — without provisioning AWS, a coding sandbox, or payments.

## Decisions

1. **Monorepo layout matches `docs/ARCHITECTURE.md`**: `apps/web`, `apps/api`, `docs/decisions`, `content/curriculum` (empty, reserved for Milestone 2 seed data), `compose.yaml` at the root.

2. **Frontend scaffolded with `create-next-app`** (App Router, TypeScript, Tailwind, ESLint, `src/` dir, Turbopack) rather than hand-rolled, to get a maintained baseline. Default template assets/copy were removed. Next.js resolved to 16.4.2 / React 19.3.0 — newer than the assistant's training data; `apps/web/AGENTS.md` (auto-generated by `next dev`) flags this for future sessions and should stay committed.

3. **Health check is a client-side fetch**, not a server-side one. `HealthStatus` is a client component that calls the API directly from the browser via `NEXT_PUBLIC_API_BASE_URL`, with explicit loading/error/success states. This exercises the real CORS configuration end-to-end (browser → Flask) rather than hiding it behind SSR, and gives Milestone 1 a pattern to extend for other client-driven data fetches.

4. **Flask app factory + blueprints**, SQLAlchemy initialized but no models yet (Milestone 1 adds the domain/topic/session models from `docs/ARCHITECTURE.md`). Flask-Migrate is initialized (`apps/api/migrations/`) with no migrations generated yet, since there is nothing to migrate.

5. **`/api/v1/health` reports both app and database status** (`SELECT 1`), so the frontend can distinguish "API up, DB down" from full health, per the "clear loading/error/empty states" requirement in `docs/PRODUCT.md`.

6. **CORS is restricted via `CORS_ORIGINS`** (default `http://localhost:3000`) rather than left open, matching the security requirement in `docs/ARCHITECTURE.md`.

7. **No shadcn/ui components installed yet.** Tailwind is present per the stack, but no UI components beyond the health status card are needed yet; adding shadcn now would be scaffolding ahead of actual use. Revisit when Milestone 1 needs real UI components (timer, exercise forms).

8. **Docker images run in dev mode** (`flask run`, `npm run dev`) with source bind-mounted, optimizing for local iteration speed over production-readiness. Production-shaped images are deferred to the Milestone 5 deployment work.

9. **Did not fix the `braces`/`eslint-config-next` transitive dev-dependency vulnerability** (`npm audit`, 5 high-severity, dev/lint-tooling only) because the suggested fix force-downgrades `eslint-config-next` to 14.2.35, which is incompatible with Next 16.4.2. Not a runtime risk; revisit when an upstream fix lands.

## Consequences
- Running `docker compose up --build` from the repo root brings up Postgres, the Flask API, and the Next.js frontend, with the frontend visibly confirming API + DB connectivity.
- No curriculum content, authentication, AWS resources, or payments were added, per the user's explicit instruction and the roadmap's scope for this milestone.

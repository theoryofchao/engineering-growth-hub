# ADR 0029: Site-wide settings panel — theme toggle, content width, lesson display defaults

## Status

Accepted

## Context

The user discovered the app had no way to manually switch light/dark mode — investigation confirmed it only ever followed the OS's `prefers-color-scheme` via CSS media query; Tailwind v4's `dark:` utilities (already used extensively across the component tree) compiled to that same media query, with no `.dark` class override configured anywhere. The user asked for a gear-icon settings panel that adds a real toggle, folds the existing per-lesson "content width" slider (ADR 0025, explicitly experimental and scoped to one page) into a site-wide setting, and asked for "other useful site-wide options" to be included. There was no shared header/nav anywhere in the app (`layout.tsx` was a bare `<html>/<body>` shell) — this is the first piece of persistent site-wide chrome.

## Decisions

1. **`next-themes`** added for theme state (`attribute="class"`, `defaultTheme="system"`, `enableSystem`, `disableTransitionOnChange`, `storageKey="egh:theme"` matching the existing key-prefix convention). `globals.css` gained `@custom-variant dark (&:where(.dark, .dark *));` so the many pre-existing `dark:` utilities respond to the class next-themes sets, and the `--background`/`--foreground` override moved from `@media (prefers-color-scheme: dark)` to `:root.dark { ... }` — next-themes' blocking script sets the class before first paint, so the media query would otherwise fight the class for a user who explicitly picks a theme opposite their OS setting.
2. **`ContentWidthContainer` generalized from a lesson-only `<main>` to every top-level page's `<main>`.** Its inline `<details>` slider UI was removed (moved into the new panel); it now takes `baseMaxWidthClassName` (default `max-w-2xl`) and a passthrough `className`, so the one page using `max-w-4xl` (home) can still get its own base width. Applied at all 7 `page.tsx` files that previously hardcoded a `max-w-2xl`/`max-w-4xl` `<main>`.
3. **A real cross-component state bug was found and fixed while building this**, not just assumed away: `useContentWidth` was a plain `useState` restored from an effect, correct when only one page's `ContentWidthContainer` ever used it at a time. Once the settings panel *and* every page's container call the hook simultaneously, each got its own disconnected `useState` instance sharing nothing but the `localStorage` key — moving the slider updated storage but had no visible effect on the page, confirmed via an actual browser run before the fix (see Consequences). Fixed by rewriting `useContentWidth` (and, for the same reason, the two new preference hooks below) on `useSyncExternalStore` with a same-tab custom `window` event dispatched on every write, so every mounted instance re-reads storage immediately rather than only the instance that changed it. This also incidentally fixed the pre-existing "flash to default before the restore effect runs" behavior, since `useSyncExternalStore`'s snapshot is read synchronously rather than after a mount effect.
4. **Two more site-wide preferences added**, both previously local-only, unpersisted `useState` inside `ContentBlocks` (`viewMode`, `showBoundaries`) with no memory across page loads: a **default view mode** (Page/Slide) and **show section boundaries by default**, each its own tiny hook (`egh:default-view-mode`, `egh:show-section-boundaries-default`) on the same `useSyncExternalStore` pattern. `ContentBlocks` applies them via a `useEffect` + "has the learner touched this control yet" ref guard, not a `useState` initializer — a plain initializer only reads a value once at first render, before it's clear anything was actually read from storage yet, so it would have silently never applied the stored preference. Once the learner manually toggles view mode or the boundaries checkbox in a session, that in-session choice wins over the default for the rest of that page view (same "sets a default, doesn't retroactively override" posture as the content-width slider).
5. **Panel UI**: a fixed gear-icon button, top-right (`src/components/site-settings.tsx`), mounted once in `RootLayout`. Pomodoro's own floating widget already occupies bottom-left/bottom-right on small/large screens respectively (`pomodoro-timer.tsx`), so top-right avoids collision. No new UI/icon library — hand-rolled inline SVG gear and the same `role="dialog"` / Escape-closes / click-outside-backdrop-button / focus-moves-in-then-returns-on-close pattern `notes-panel.tsx` already established, rather than inventing a second modal convention.

## Consequences

- `vitest run`: 143 passed (128 before this slice + 15 new — two new hook test files, `site-settings.test.tsx`, plus `content-width-container.test.tsx` rewritten for its new shape now that the slider UI moved out of it). `tsc --noEmit`/`eslint`/`prettier --check`: clean. `next-themes` added to `apps/web/package.json`.
- No backend changes this slice.
- Verified against the live dev stack with a real browser (Playwright): toggling Dark/Light actually changes the computed body background color and persists across a reload (confirmed the `.dark`/`.light` class on `<html>` survives); confirmed via a first, failing run that the content-width slider silently did nothing to the page before the `useSyncExternalStore` fix, then confirmed it correctly resizes the lesson's `<main>` after the fix; confirmed setting "default view: Slides" and "show boundaries by default" on one page took effect on a *subsequent, fresh* navigation to a lesson page; confirmed Escape and the click-outside backdrop both close the panel and return focus to the gear button; zero console/page errors throughout.
- Not done: no attempt to sync theme/preferences across devices or tabs beyond the same-tab `useSyncExternalStore` event (a real `storage` event listener for cross-tab sync within one browser was considered out of scope — this is a single-user personal tool, not a collaborative one). The Monaco editor font-size (hardcoded in `exercise-code.tsx`) was identified as a plausible future addition to this panel but not built now, to keep this slice's scope to what was asked.

# ADR 0012: Claude Code native-toolkit lesson (MCP, Skills, Hooks, LSP, context hygiene)

## Status
Accepted

## Context
User request: build a lesson based on the community guide at `github.com/TheDecipherist/claude-code-mastery` (Claude Code's CLAUDE.md hierarchy, MCP servers, Context7, Skills, Hooks, LSP, and the "single-purpose chats" discipline), sized consistently with the existing AI-Assisted Software Development content.

Investigation before writing content:
- Module 70 (subtopic 70.9, added by ADR 0011) already covers *choosing* a coding-agent toolchain, but nothing yet covered Claude Code's own built-in mechanisms for enforcing the plan-review-verify discipline from sessions 1–5. This is new ground, not a duplicate of existing sessions.
- `content/curriculum/ai-assisted-software-development.json`'s existing 5 sessions are the sizing reference the user pointed at: measured directly, 6–7 content blocks per session, block bodies ~460–1840 characters (~75–300 words, most clustering 900–1500 chars), most non-wrap-up blocks carrying 1–2 slide-pinned multiple-choice exercises, every session ending in a short no-exercise "bottom line" block. ADR 0009 is the origin of this convention ("most blocks went from ~300-800 characters to ~900-1800" after a deliberate depth pass).
- Pulled the source guide's actual outline (its GUIDE.md) rather than working from the README alone, to scope the 8-part structure (CLAUDE.md hierarchy, scaffolding rules, MCP, Context7, Skills, single-purpose chats, Hooks, LSP) accurately, including which cited statistics (39% multi-turn drop, 900x LSP speedup, Docling 97.9%) are independently verified vs. single-source claims worth flagging as such to learners — consistent with this module's existing skepticism-of-unverified-claims stance (session 2's "Productivity Reality Check").

## Decisions
1. **Added a 6th learning session** to `content/curriculum/ai-assisted-software-development.json`: "Claude Code's Native Toolkit: MCP, Skills, Hooks, and Context Hygiene" (25 min, free tier, 7 content blocks, 6 slide-pinned multiple-choice exercises), the same way ADR 0011 added session 5. Covers MCP servers (incl. Context7 and the token-cost tradeoff), Skills (progressive disclosure, the ~20%-of-conversations rule of thumb), Hooks (deterministic enforcement, exit codes 0/1/2), LSP (semantic code intelligence, with the 900x figure explicitly flagged as unverified), and `/clear` context hygiene (citing the arXiv multi-turn study and Chroma's context-rot research). Closes on a block tying all five back to the module's running theme: habits become infrastructure.
2. **Sized to match ADR 0009's established convention, not re-derived from scratch**: measured the existing corpus first (see Context), then authored all 7 blocks inside the 900–1800 char / ~140–300 word range (actual: 965–1442 chars). Followed the existing pattern of 0 exercises on the opening/closing blocks and 1–2 on teaching blocks, including giving the densest block (Hooks, two distinct concepts — suggestion-vs-rule and exit-code semantics) 2 exercises rather than 1, same as several existing blocks in sessions 1 and 3.
3. **Added subtopic `70.10`** ("Claude Code's native tooling (MCP servers, Skills, Hooks, LSP) and single-purpose-chat context hygiene") to `CURRICULUM.md`, additive per the file's own ID-stability rule — no renumbering of `70.1`–`70.9`.
4. **Ran ADR 0009's exercise-quality audit programmatically** before and after authoring: first pass flagged 3 of 6 new exercises as "correct answer is the uniquely longest option" (50%, well above the ~20–25% baseline the existing corpus holds to); rebalanced option wording on all 3 until 0 of 6 were flagged, without changing which answer is correct or watering down the explanation.
5. **Verified against the live stack**, not just `pytest`: confirmed the dockerized API container can't run `flask seed` directly (`content/curriculum/` isn't bind-mounted into the `api` service in `compose.yaml` — a pre-existing gap, not introduced here), seeded instead from the host venv against the same Postgres (exposed on `localhost:5432`), then confirmed via direct SQL and the live `GET /api/v1/learning-sessions/7` response that: the session landed with exactly 7 blocks and 6 exercises (no orphaned rows from the upsert), reseeding after the option-rebalance correctly updated the existing rows in place, and the API response never leaks `correct_index`/`explanation` to the client.

## Consequences
- `pytest`: 29 tests pass. Updated the same two hardcoded session-count assertions ADR 0011 flagged as needing a sweep on any new session: `test_seed.py`'s `len(ai_topic.learning_sessions) == 5` → `6`, `test_learning_sessions.py`'s `len(body["topic_sessions"]) == 5` → `6`.
- No migration, no schema/route/frontend change — pure content addition through the existing seed pipeline.
- Confirmed the `compose.yaml` → `flask seed` path is broken for anyone relying on `docker compose exec api flask seed` going forward (works fine run from the host venv against the exposed Postgres port instead); worth a follow-up fix (bind-mount `content/` into the `api` service) if/when seeding becomes a more frequent workflow, but out of scope here since it predates this change and a workaround exists.
